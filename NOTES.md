# Notes

Decisions and operational context for the no-LLM NGS results interpreter.

## Decisions — 2026-09-28

* **DECIDED — legacy product removal.** The repository contains one product: the deterministic v1 results interpreter. The obsolete LLM and pipeline-execution implementation and its tests are removed.
* **DECIDED — `ngs` script reassignment.** The sole console command is `ngs`, provided by `doors.cli:main`. It accepts an input path and returns the v1 verdict surface. No legacy command alias remains.
* **DECIDED — scope.** VCF support is call-quality QC only. Variant interpretation (pathogenicity, gene context, ACMG), pipeline execution, network calls, and LLM use are out of scope. `UNKNOWN` remains valid whenever evidence is insufficient.
* **DECIDED — thresholds.** Threshold values and rule semantics are unchanged. Defaults are documented in the README and at the top of the two primary QC and audit rule modules; expert sign-off is pending and labs should tune by assay type.

## Product architecture

`core/` contains parsing, sniffing, rules, assessment, diagnosis, reports, and the evidence model. `doors/` is limited to CLI/web input and presentation. Every finding must retain a valid rule receipt and evidence receipt, including source file, location, and hash where applicable.

Supported inputs and known limits are documented in [README.md](README.md) and [ROADMAP.md](ROADMAP.md). The case study demonstrates a cross-file run audit in [CASE_STUDY.md](CASE_STUDY.md). CLI behavior is documented in [CLI_USER_GUIDE.md](CLI_USER_GUIDE.md).
