# Case study: the run where every step exited 0

**Input:** an RNA-seq run folder — alignment, counts, QC metrics, execution
trace. **Symptom:** none. All four pipeline steps reported success.

**Verdict:** `Fix this and re-run` — 18% of reads assigned to genes because the
alignment and the gene list name chromosomes differently.

```bash
.venv/bin/python -m doors.cli fixtures/runs/contig_mismatch
```

## What the tool said

> **Problem — Reads and gene annotation are naming chromosomes differently.**
>
> *What it is:* Only 18% of reads were assigned to genes. The aligned reads
> name their chromosomes like '1', but the gene list used for counting names
> them like 'chr1'.
>
> *What it means:* The aligner and the gene annotation are working from two
> different dictionaries of chromosome names, so most reads have no gene to be
> counted against. Every step reported success, which is exactly why this one
> gets published by mistake: the counts are real numbers describing almost
> nothing. Differential expression from this run would be meaningless.
>
> *Do this:* Re-run quantification using the annotation that matches the genome
> the reads were aligned to (same source, same chromosome naming). You do not
> need to re-align.

## The receipts behind it

Every number above traces to a file and a line. This is the actual receipt
block from the run (hashes identify the exact bytes judged):

```
AUD-STRAND-01: rule:AUD-STRAND-01 @ bam contigs vs annotation contigs,
               assignment rate
AUD-STRAND-01: file:8ee3e4f33024 @
               counts/sample1.featureCounts.txt.summary:line=2
               — Assigned 1,800,000 of 10,043,000 counted reads = 17.9%
AUD-STRAND-01: file:8e5658148f4b @
               star/sample1/Aligned.sortedByCoord.out.bam — 25 @SQ contigs
AUD-STRAND-01: file:3420f4695f6e @
               annotation/gencode.v45.annotation.gtf — 25 contigs in column 1
```

Three independent files agree on the story: the counts summary shows the
collapse (17.9%), the alignment header shows one naming style (25 Ensembl
contigs: `1, 2, …`), the annotation shows the other (25 UCSC contigs:
`chr1, chr2, …`). No single file looks wrong on its own — the failure only
exists *between* files, which is why per-step exit codes miss it.

## Why this one matters

* **Silent.** Nothing failed, nothing warned. Without a cross-file check, this
  run produces a counts table, a DE list, and a figure — all meaningless.
* **Cheap to fix.** No re-sequencing, no re-alignment: re-run quantification
  with the matching annotation.
* **Reproducible.** The input above is `fixtures/runs/contig_mismatch`, shipped
  with the repo and regenerated byte-identically by
  `python scripts/make_fixtures.py`. Run the command and you get this verdict.

More failures of this shape — the ones that exit 0 and corrupt results
quietly — are documented with the audit rules in the README (`AUD-STRAND-01`
through `AUD-ALIGN-01`).
